1. REPOSITORY AUDIT & DISCOVERABILITY BASELINE
--------------------------------------------------------------------------------
- Organization: ellmos-ai
- Umbrella Ecosystem: open-bricks
- Primary Category: AI Infrastructure & Systems Cartography / Architecture Drift Detection
- Core Positioning: Evidence-backed system cartography and architecture drift detection engine. Separates desired system functions from concrete function carriers (skills, modules, MCP interfaces, CLI tools, actors) and provides cryptographic proof of coverage, gaps, overlaps, and negative assertions without mutating scanned codebases.
- Distinct Value Proposition:
  * Two-Layer Function vs. Carrier Separation: Clarifies whether an expected capability is actually provided by an evidenced component or merely assumed in prompts/documentation.
  * Local SQLite Evidence Store: Persists locators, URIs, and SHA-256 content digests rather than duplicating full text or confidential data.
  * Cryptographic Receipt Verification: Ed25519-signed actual-self search receipts verified against local content-hashed trust stores with pinned keys.
  * Fail-Closed Anti-Drift Engine: Any missing authority receipt, key mismatch, or unevidenced capability triggers an immediate quarantine/blocked state.
  * 100% Local-First & Zero-Egress: Operates entirely offline; local web dashboard binds strictly to 127.0.0.1:8765 with zero telemetry.
- Sibling Ecosystem Integration: Interlocks with `ellmos-ai/policy-registry` for governance contracts, `ellmos-ai/coma` for context management, `ellmos-ai/ellmos-controlcenter-mcp` as tool execution plane, and developer tools across `dev-bricks` and `open-bricks`.

2. TARGET PERSONAS & USER JOURNEYS
--------------------------------------------------------------------------------
1. Autonomous AI Agent Engineers & Multi-Agent Swarm Architects
   - Needs: Formulate clear capability boundaries and understand which tools, skills, and MCP endpoints are available, verified, and safe to execute.
   - Pain Points: Multi-agent systems suffer from tool collision, hallucinated tool availability, and conflicting skill declarations across repositories.
   - Solution: Query `system-explorer` evidence maps via CLI or exported JSON to verify actual capability coverage before invoking agent tools, with fail-closed quarantine on drift.

2. Enterprise System Architects & SREs (Architecture Drift Detection)
   - Needs: Track deviation between intended system designs (desired functions) and actual code implementations (function carriers) across complex multi-repo ecosystems.
   - Pain Points: Microservices and agent swarms evolve rapidly, leading to silent architectural drift, obsolete interfaces, and unevidenced dead code.
   - Solution: Run bounded, reproducible scans with time budgets; generate automated architecture diffs, coverage reports, and Mermaid visual diagrams.

3. Local-First & Sovereign Software Developers
   - Needs: Inspect system topology, module relationships, and peripheral software resources on local workstations without cloud dependencies or telemetry.
   - Pain Points: Cloud-based APM and enterprise cartography tools require SaaS subscriptions, outbound network connections, and leak proprietary IP.
   - Solution: 100% local-first CLI and loopback web UI (`127.0.0.1:8765`), unprivileged user-mode execution (RunAsInvoker), and zero network egress.

4. Security, Compliance & Governance Auditors
   - Needs: Validate that system components have verified provenance, non-elevation boundaries, cryptographic receipt signatures, and compliant open-source licenses.
   - Pain Points: Black-box agent frameworks execute untrusted code without audit trails or proof of capability ownership.
   - Solution: Ed25519-signed actual-self receipts, SHA-256 content pinning, audited 100% permissive open-source stack, and codified 48h response / 5-day triage security SLA.

5. GOVERNANCE & RUNTIME INVARIANTS
--------------------------------------------------------------------------------
- INV-LOCAL-01: 100% Local-First & Zero Network Egress (All scanning, parsing, and storage operate offline; web UI strictly binds to loopback 127.0.0.1:8765).
- INV-EVID-02: Immutable Evidence & Content Checksums (Original files remain intact; SQLite store records URIs, locators, and SHA-256 digests without storing private prompts or raw payloads).
- INV-FAIL-03: Fail-Closed Resolution & Anti-Drift (Missing receipts, hash drift, expired key pins, or unevidenced claims trigger immediate quarantine; zero heuristic guessing).
- INV-RO-04: Read-Only Governance & Zero Target Mutation (Generates maps, coverage matrices, and proposals without modifying target source trees or external registries).
- INV-NON-05: Non-Elevation & Unprivileged Execution (Executes entirely within user-mode space under RunAsInvoker without administrative elevation).
- INV-SCOP-06: Strict Scope & Host Isolation (Instances on distinct physical machines are strictly segregated; cross-host merging of identical names is rejected).
- INV-ED25519-07: Cryptographic Receipt Integrity (Actual-self and search authority receipts require Ed25519 signatures verified against pinned public keys).
- INV-TIME-08: Bounded Scan Time & Transactional Rollback (Root scans execute within configurable deadlines; cancellations trigger atomic SQLite transaction rollbacks).
- INV-CROSS-09: Cross-Platform Parity & Multi-Host Sync Resilience (Paths and manifests normalized across Windows, Linux, macOS; resilient against cloud conflict files and locks).
- INV-SLA-10: 48h Security Response & 5-Day Triage SLA (Vulnerabilities acknowledged within 48 hours and triaged within 5 business days under coordinated disclosure).
